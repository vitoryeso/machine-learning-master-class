Dois otimizadores para o mesmo modelo e a mesma loss (MSE), num problema 2D. Batch Gradient Descent (gradiente sobre todos os N, 1 passo/época) vs LMS / Widrow-Hoff (atualiza por exemplo, N passos/época). Rust puro, sem libs de ML.

Método e derivação do gradiente

Derivação (MSE)

L = (1/N)·Σ(ŷ−y)²,  ŷ = wᵀx + b
∂L/∂w = (2/N)·Σ(ŷ−y)·x
∂L/∂b = (2/N)·Σ(ŷ−y)

O fator 2 é absorvido no learning rate.

As duas regras

GD : w ← w − α·(1/N)·Σ(ŷ−y)·x   (α=0.01)
LMS: w ← w + η·(y−ŷ)·x          (η=0.001)
     ↑ por exemplo, online

200 épocas: GD dá 200 passos; LMS dá 200×300 = 60.000.

  • x — features de entrada; ŷ — previsão; y — alvo real.
  • w, b — pesos e viés (o que se treina).
  • N — nº de exemplos; Σ — soma sobre eles.
  • α, η — learning rate (passo) do GD e do LMS.

Conclusão — o trade-off

LMS venceu aqui

  • 60k passos > 200 → convergiu perto do ótimo.
  • Ideal p/ dados grandes / streaming.

Não é grátis

  • GD é mais estável (sem oscilação).
  • LMS com lr grande diverge.

O eixo central: gradiente exato com poucos passos (GD) vs muitos passos ruidosos (LMS) — mesmo custo O(Nd) por época, estratégias opostas. A escolha do learning rate é crítica e independente para cada um (robusto no multi-seed: gap ≫ std).
